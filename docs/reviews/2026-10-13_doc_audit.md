## 3. Config/CLI examples that fail if followed verbatim

| Doc | Issue |
|---|---|
| `docs/user-guides/cluster-setup.md` | 🔴 Sample `cluster.env` omits `POD_SUBNET` (hard-required by `07-install-eks-d.sh`, used as `networking.podSubnet`) and `AWS_ACCOUNT_ID` (required by `13-install-ebs-csi.sh` and `15-install-karpenter.sh`). Following the doc's dev-mode heredoc as written will fail at kubeadm init. |
| `docs/user-guides/node-pools.md`, `docs/user-guides/components.md` | 🔴 EC2NodeClass examples use `role: <tenant-id>-eks-d-worker-node-role` and `amiFamily: AL2023`. Actual manifests (`node-pools/chart/templates/ec2nodeclass.yaml`, `spot-nodepool.yaml`, `ondemand-nodepool.yaml`) use `instanceProfile:` and `amiFamily: Custom` — the project's own design doc (`10-karpenter-requirements.md`) explains `role:` can't be used because there's no IAM VPC endpoint, and `AL2023` alias hits a known Karpenter v1.10 bug. |
| `docs/user-guides/node-pools.md` | 🔴 Helm example passes `--set workerRole=my-tenant-eks-d-worker-node-role` — chart's `values.yaml` has no `workerRole` key; this is a silent no-op. Real key is `instanceProfile` (set by `configure-nodepools.sh` to `ecp-tenant-<id>-ir`). |
| `docs/user-guides/node-pools.md` | 🟡 NodePool `consolidateAfter`/`limits` values shown don't match any single source: standalone YAMLs use `30s` + `cpu/memory 1000/1000Gi` + `expireAfter`, doc shows `1m`/`5m` and `100`/`100Gi` with no `expireAfter`. |
| `docs/user-guides/self-managed-quick-start.md` step 4 | 🔴 IAM policy-attach command has a literal copy-paste bug — the same `--policy-arn` argument is duplicated in one `aws iam attach-role-policy` call, making the shown command invalid as written. |
| `docs/DEPLOYMENT_BUNDLE.md`, `docs/user-guides/deployment.md` | 🟡 Bundle directory layout shown as `infra/cdk.out/`, `control-plane/cdk.out/`, artifact name `ecp-cdk-{ver}.tar.gz`. Actual `bundle/Dockerfile` copies `infra-cdk/` to the image root and `control-plane-cdk/` to `control-plane/`; actual release artifact name is `express-compute-control-plane-{ver}.tar.gz`. Doc also omits that `ami-signatures.json`, the signing pub key, and `verify-ami.sh`/`import-ami.sh` are copied into the bundle. |

## 4. Design-doc inconsistencies (lower urgency — mostly internal/dev docs)

- `docs/design/k3s-xpress-ga-plan.md` is broadly stale: claims Flannel is the default CNI (code always disables Flannel and installs VPC CNI unconditionally), claims "no Karpenter at GA" (Karpenter ships and is wired into `setup-k3s-xpress.sh` step 7/8), claims `local-path-provisioner` is default storage (actual default is EBS CSI `gp3`, annotated `is-default-class: true`), and references a non-existent `ecp-boot.service` (real unit: `k3s-xpress-boot.service`).
- `docs/design/k3s-cli-and-ssm-contract.md`: states boot timeout is 120s for k3s; actual systemd unit sets `TimeoutStartSec=300`. Also claims k3s needs no VPC CNI/ENI IAM permissions ("no VPC CNI") — contradicted by the same repo's `install-vpc-cni.sh`, which is always invoked.
- `docs/design/ami-builder-modularization.md` status header says "Accepted, pending implementation" and describes `install.sh` as "a 517-line monolith." The modularization is fully shipped: `ami-builder/scripts/components/` contains all 8 proposed component scripts, and `install.sh` is 275 lines using the component-loop pattern the doc proposes. Just needs the status flipped to "Implemented."
- Worker IAM instance-identity naming is inconsistent across three docs: `eks-d-workstation-<signum>`, `ecp-workstation-<signum>`, and the actual code value `ecp-tenant-<id>-ir` (`node-pools/configure-nodepools.sh`).
- `docs/design/aws-ec2-setup/*.md` files reference old numbered-script names (`07-install-cni.sh`, `10-install-ebs-csi.sh`, `install-all.sh`, `08-install-coredns.sh`) that no longer exist in `cluster-setup/`. These docs are already labeled historical in their own `README.md` index, so this is expected drift, not a defect — included for completeness only.
